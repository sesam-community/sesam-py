# Purpose and Scope

Document this repository as the Sesam command-line client and connector-development tooling, not as the Sesam runtime or a generic Python SDK. Serve engineers synchronizing configuration, working on connector templates, interpreting test output, or changing CLI behavior, and coding agents locating precise implementation contracts. Prefer roughly eight to ten substantive pages, grouping commands by workflow and risk rather than creating a page per flag or method. Follow inspected complexity rather than enforcing a page quota.

# Sesam Knowledge Network

Sibling checkouts are independent repositories, not extra source roots. `lake` owns datahub execution/API behavior, `docs` owns the product and configuration/DTL reference, `portal` owns management behavior, `webconsole` owns its UI, `sesam-exporter` owns Prometheus monitoring, `sesam-lineage` owns lineage inference/service behavior, and `counting-semaphore` owns its separate service. This project imports an external `sesamclient` package; do not identify that dependency with this CLI repository or the exporter/lineage classes merely because names overlap.

Describe only locally evidenced endpoints and integration relationships. Name the repository/topic that owns unanswered questions; do not read siblings or machine-level configuration to fill gaps. Verify cross-wiki targets through a linked OpenWiki workspace if available; otherwise record a not-yet-linked handoff. Use portable links without machine-specific absolute paths. Each wiki must work independently and later be searchable together through `openwiki link`.

# Boundaries

Honor `.openwikiignore`. Never reproduce JWTs, OAuth/access/refresh tokens, client secrets, API keys, private keys, real subscription/customer identifiers, credential files, or production configuration/testdata dumps. Allowed README/examples/fixtures may still contain sensitive literals; redact them and use synthetic placeholders. Do not run the CLI or login helpers, ingest traces, install dependencies, build/package/publish releases, start callback servers, execute remote integration tests, reset/wipe nodes, update expected output, or contact production while researching. Generation may write only OpenWiki-managed documentation/metadata and its normal managed agent-navigation blocks; preserve all existing contributor guidance, source, templates, tests, expected fixtures, hooks, and build inputs.
